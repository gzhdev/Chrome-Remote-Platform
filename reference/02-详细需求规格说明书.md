## 1. 文档目的

本说明书作为架构评审、系统研发、测试验收和部署运维的统一依据。对象包括：客户端 SDK、中央 Browser Control Server、Secure CDP Gateway、Windows Browser Service、Chrome for Testing 运行环境及最小管理界面。

## 2. 背景、用户角色与目标

### 2.1 背景

Browser Use 1.0 使用原生 CDP 操作浏览器。项目需要把浏览器从运行 Agent 的机器上拆出来：Browser Use 可在用户电脑或测试服务器上运行，Chrome 在远程 Windows 虚拟机中运行，统一由中央服务提供安全访问和多用户资源管理。

### 2.2 主要目标

- **G-01**：用户无需自行运行 Chrome，仅通过中央服务获得 Browser Use 可连接的远程浏览器。
- **G-02**：支持 Windows 可见浏览器，初期仅网页操作，支持截图；后续能够回显页面。
- **G-03**：单 Windows 节点默认运行最多 4 个独立 Chrome，实例数由配置读取且可修改；中央支持多节点横向扩容。
- **G-04**：整体支持 20+ 并发浏览器控制任务，以单实例单控制租约为安全基线。
- **G-05**：Windows 节点主动连接中央服务，跨网段/NAT 部署不依赖对节点开放入站端口。
- **G-06**：正确处理浏览器复用、Profile 权限、租约超时、异常断线、节点重连及并发竞争。
- **G-07**：清晰的管理 API、审计与可观测性，为后续 Viewer 与浏览器工件传输提供接口基础。

### 2.3 角色与权限

| 角色 | 简述 | 允许动作 |
|---|---|---|
| Platform Admin | 平台管理员 | 节点/用户/凭据管理、全局策略、强制回收与审计 |
| Project Admin | 项目管理员 | 管理项目 Profile 与授权、查看项目浏览器与租约 |
| Operator | 自动化测试用户 | 申请已授权 Profile 的浏览器、连接、续租、释放、获取授权截图 |
| Viewer（V2） | 只读观察者 | 观看被授权页面帧，不具备 CDP 操控权限 |
| Node | Windows Browser Service | 仅维护自身节点、接受中央授权指令、主动建立隧道 |
| System | 中央调度系统 | 在资源与租约状态一致前提下进行分配和撤销 |

**权限默认拒绝**。Profile 默认仅其所属用户/项目有权访问。管理员并不因此免于操作审计。

## 4. 系统边界和假设

- Agent 及 LLM 推理位于客户端；中央不托管任务提示词或模型密钥。
- 中央服务入口通过有效 TLS 证书对用户及节点可达；Windows 节点能主动对中央建立出站 HTTPS/WSS。
- Windows 登录用户为专用、低权限账号；RDP 断开后保持交互式会话，**注销或重启不保证浏览器进程继续存活**。
- Chrome for Testing 版本固定；Browser Use 1.0.x 版本也固定。当前候选为 `browser-use==1.0.6`，以 PoC 通过的具体版本为最终运行基线。
- Windows Profile 逻辑隔离不等同强租户隔离。对彼此不信任的租户，必须使用独立 Windows 用户会话或 VM。

## 5. 详细功能需求

### 5.1 节点生命周期与注册（NODE）

| ID | 优先级 | 功能要求 | 验收标准 |
|---|---|---|---|
| NODE-001 | P0 | Windows Worker 必须使用一次性注册码完成首次注册，产生稳定 `node_id` | 同一注册码再次使用失败；节点无法自报任意其他 ID |
| NODE-002 | P0 | Worker 必须**主动**使用 WSS/TLS 建立中央控制长连接 | Windows VM 不开放外网入站端口时仍能正常上线 |
| NODE-003 | P0 | 控制连接必须使用节点专属凭据认证；中央校验其绑定节点 ID | 篡改 node_id、使用撤销凭据均被拒绝 |
| NODE-004 | P0 | 启动连接后上报节点版本、OS、Windows 会话、Chrome 版本、`max_instances`、现存实例摘要 | 管理端可见，且与本机实际配置/状态一致 |
| NODE-005 | P0 | 心跳、超时、重连必须可配置，默认心跳 10 秒、失联 35 秒 | 故障注入时节点及时从 ONLINE 变为 OFFLINE，停止新任务分配 |
| NODE-006 | P0 | 节点重连需以新 `connection_epoch` 替代旧连接，并执行实例对账 | 旧连接命令被拒；不重复创建已存活的 Chrome |
| NODE-007 | P1 | 允许管理员执行 Drain，停止新分配但保留现有业务直到释放 | 新请求不分配 Drain 节点；现有租约可继续完成 |
| NODE-008 | P1 | 节点凭据支持轮换、吊销与凭据过期前更新 | 凭据轮换不影响其他节点；旧凭据失效 |
| NODE-009 | P1 | 登记节点支持项目/节点标签、浏览器版本和可达目标环境标签 | 调度可基于标签筛选；非法标签被拒绝 |

### 5.2 Windows 浏览器实例（BROWSER）

| ID | 优先级 | 功能要求 | 验收标准 |
|---|---|---|---|
| BROWSER-001 | P0 | 使用 Chrome for Testing 启动可见窗口；Worker 在已登录 Windows 的交互式会话运行 | RDP 查看得到 Chrome 窗口，Browser Use 能进行 CDP 网页操作 |
| BROWSER-002 | P0 | 每个实例必须使用独立 Profile 目录、进程关联信息、CDP 端口和下载目录 | 两个实例的 Cookie、LocalStorage 与进程归属不混用 |
| BROWSER-003 | P0 | 默认 `max_instances=4` 从节点配置读取；中央策略可进一步下调有效上限 | 4 个占用名额时第 5 个新建请求被拒；改配置重载后按新阈值生效 |
| BROWSER-004 | P0 | 实例创建与容量预留必须原子化，含 CREATING/STARTING/STOPPING 等状态计数 | 10 个并发创建请求时实际同时启动数不超过有效上限 |
| BROWSER-005 | P0 | Chrome 启动使用动态 CDP 端口（`--remote-debugging-port=0`），从 `DevToolsActivePort` 读取并复核 | 无端口冲突；发现过程超时返回明确错误 |
| BROWSER-006 | P0 | CDP 仅监听 `127.0.0.1`；对客户端不返回直接可用的本机端点 | 从远程网络无法连接节点原始 CDP 调试端口 |
| BROWSER-007 | P0 | 启动/停止/重启/状态查询使用统一状态机与错误码 | 所有状态转换可查询，非法转换按规则拒绝 |
| BROWSER-008 | P0 | 运行中 Profile 必须独占锁定，跨实例重复挂载受阻 | 两请求同时指定 Profile，至多一个成功 |
| BROWSER-009 | P0 | Worker 重启必须尝试恢复已存活实例，不允许盲目重新启动 | 模拟 Worker crash 后现有 Chrome 能正确重新关联或安全隔离 |
| BROWSER-010 | P0 | Worker 停止实例必须确认进程退出和锁释放后再释放容量 | 超时强杀进程树时无持续占用端口的孤儿进程 |
| BROWSER-011 | P1 | 健康探测区分 Chrome 进程存活、CDP 可用和 Agent 租约状态 | Chrome 卡死时不误报 READY；健康恢复有审计记录 |
| BROWSER-012 | P1 | 控制台可查看当前浏览器与页面目标，管理仅允许符合权限的实例 | 非授权用户看不到其他私有 Profile 内容 |
| BROWSER-013 | P1 | 任务结束后持久化实例默认保留，临时 Profile 按清理规则删除 | 复用后可保留登录；临时用户环境无跨任务状态泄漏 |
| BROWSER-014 | P1 | 节点资源不足时可拒绝启动，即使运行实例尚未达到 max | 高内存压力或 CPU 阈值场景被明确拒绝并反馈原因 |

### 5.3 Profile 与会话隔离（PROFILE）

| ID | 优先级 | 功能要求 | 验收标准 |
|---|---|---|---|
| PROFILE-001 | P0 | Profile 具有独立 ID、归属主体、模式（persistent/ephemeral）和 ACL | 未授权用户申请 Profile 被拒；操作可追溯 |
| PROFILE-002 | P0 | 同一 Profile 不能同时在两个 Chrome 实例上运行 | 跨节点竞争只有一个成功，第二个得到 `PROFILE_IN_USE` |
| PROFILE-003 | P0 | 一个 Profile 关闭 Chrome 后可在授权用户下重新加载 | Cookie/登录状态按 Chrome 与目标站点实际规则保留 |
| PROFILE-004 | P0 | Profile ID 不允许映射任意磁盘路径；路径必须在 Worker 指定根目录内 | `..`、绝对路径、符号链接越界等被拒绝 |
| PROFILE-005 | P1 | Profile 删除需二次确认和权限校验，且无运行实例占用 | 正在使用时返回冲突，成功删除后有审计记录 |
| PROFILE-006 | P1 | 跨用户共享必须显式授权，默认私有 | 用户 B 不能自动使用用户 A 的已有登录状态 |
| PROFILE-007 | P1 | Profile 可设置节点亲和性以减少跨节点搬运 | 调度不会在未经迁移的节点自动启动已绑定 Profile |

### 5.4 全局调度与排队（SCHED）

| ID | 优先级 | 功能要求 | 验收标准 |
|---|---|---|---|
| SCHED-001 | P0 | 请求浏览器时优先复用有权限的 READY 空闲实例，再创建新实例 | 已存在合适空闲实例时不多建 Chrome |
| SCHED-002 | P0 | 调度排除 OFFLINE、DRAINING、认证失败节点及健康异常实例 | 故障节点永不被分配新请求 |
| SCHED-003 | P0 | 中央预留与节点本地上限双层检查 | 并发竞争、状态延迟下仍不会超过节点容量 |
| SCHED-004 | P0 | 若当前节点已满，尝试其他匹配节点；全部满时按策略排队或返回资源不足 | 3 节点中一个满时仍可分配其他节点 |
| SCHED-005 | P0 | 创建命令携带 Idempotency Key 与 deadline，超时必须查询后对账 | HTTP 重试不会创建多个实例或重复扣减资源 |
| SCHED-006 | P1 | 等待请求可设置排队超时，支持取消，取消后释放预留 | 等待超时/取消不产生孤儿实例或租约 |
| SCHED-007 | P1 | 提供调度失败原因和资源统计，例如节点全满/无匹配标签/Profile 被占用 | 客户端获得可处理的错误码，不使用模糊 500 |
| SCHED-008 | P1 | 允许中央设置 per-user/per-project 并发配额 | 某用户占满自己的配额不会阻塞其他可用用户的授权申请 |
| SCHED-009 | P2 | 支持排队优先级、公平性策略与管理干预 | 规则可配置、无长期饥饿（以压测定义） |

### 5.5 独占租约（LEASE）

| ID | 优先级 | 功能要求 | 验收标准 |
|---|---|---|---|
| LEASE-001 | P0 | 同一实例最多一个**有效控制租约**，通过数据库原子约束保证 | 两并发请求只有一个 ACTIVE 控制租约 |
| LEASE-002 | P0 | 租约绑定租户/用户、Profile、instance_id、有效期和单调递增的 `lease_epoch` | 不同用户不可伪造或借用租约 |
| LEASE-003 | P0 | 默认租约 TTL 120 秒、SDK 每 30 秒续租，均支持配置 | 在测试未结束且续租正常时不自动回收 |
| LEASE-004 | P0 | 客户端断线进入默认 60 秒的恢复宽限期 | 同一用户合法重连可恢复，其他用户不能提前获得控制权 |
| LEASE-005 | P0 | 到期或强制撤销时必须先关闭旧 CDP 通道并由节点 fencing 确认 | 模拟旧 Agent 不退出，新用户仍不会与旧 Agent 双控 |
| LEASE-006 | P0 | 释放租约不自动结束持久化 Chrome；Agent 生命周期与浏览器生命周期解耦 | Agent 退出后实例仍 READY、可按 ACL 复用 |
| LEASE-007 | P0 | 使用 lease_epoch/instance generation 防止迟到命令重复操作 | 旧代际的 OPEN_TUNNEL、RENEW、STOP 被拒绝 |
| LEASE-008 | P1 | 管理员可强制撤销租约，须记录操作者与原因 | 旧 WSS 被关闭，操作在审计中可追溯 |
| LEASE-009 | P1 | 租约状态与数据通道状态分开存储 | 数据通道断开不立即重置实例或删除租约 |

### 5.6 控制 WSS（CTRL）

| ID | 优先级 | 功能要求 | 验收标准 |
|---|---|---|---|
| CTRL-001 | P0 | 控制消息必须包含 `protocol_version`、`type`、`message_id`、`request_id`、`deadline_at`、`payload` | 无效结构按协议错误返回，不执行操作 |
| CTRL-002 | P0 | Node 登录、欢迎、快照、心跳、命令、结果各类型定义明确 | 消息双方使用同一 Schema/Pydantic 进行校验 |
| CTRL-003 | P0 | 控制指令必须有幂等语义；重复 message_id 不能重复启动/停止 | 故意重放 CREATE_BROWSER，不增加实例 |
| CTRL-004 | P0 | 断线重连后旧连接事件被忽略，状态以新一代 snapshot/对账为准 | 旧连接延迟响应不能覆盖新状态 |
| CTRL-005 | P0 | 控制连接超时、TLS 证书、凭据拒绝应有明确日志与健康指标 | 故障能从节点日志和中央监控定位 |
| CTRL-006 | P1 | 事件/命令协议支持向后兼容的版本号，并拒绝不兼容 major version | 旧 Worker 不会静默误执行新指令 |

### 5.7 CDP 安全数据代理（CDP）

| ID | 优先级 | 功能要求 | 验收标准 |
|---|---|---|---|
| CDP-001 | P0 | Gateway 暴露 Browser Use 可连接的浏览器级 WSS CDP 地址 | Windows Chrome 网页导航、点击、DOM/Target 查询成功 |
| CDP-002 | P0 | 每次 CDP 连接使用**短期一次性票据**，绑定 lease、instance、用户和目标网关 | 过期/重放/错租约票据均拒绝 |
| CDP-003 | P0 | Windows Node 按控制指令主动建立独立 WSS 数据隧道；中央不能主动访问节点 CDP 端口 | 断开 Windows 入站端口，仍能完成 CDP 连接 |
| CDP-004 | P0 | `tunnel_id`、节点身份、实例归属、租约代际和一次性 nonce 配对验证 | 假冒节点连接或错实例 tunnel 被拒绝 |
| CDP-005 | P0 | 双向透明转发 CDP WebSocket 文本及必要的二进制帧，支持背压、大小限制和合理空闲心跳 | 连续运行 1 小时未出现消息串线或非预期断链 |
| CDP-006 | P0 | 同一个控制租约 V1 最多一条活动写 CDP 连接；重连前必须关闭/替换旧连接 | 第二个有效写连接不能同时控制浏览器 |
| CDP-007 | P0 | 当租约被撤销或节点失联，Gateway 关闭对应连接并拒绝新的连接 | 用户无权限后不能继续操作 |
| CDP-008 | P0 | 不向普通客户端暴露原生 Chrome CDP URL、节点真实 IP、Windows Profile 路径 | 只返回中央统一入口与逻辑浏览器 ID |
| CDP-009 | P0 | 与 Browser Use 1.0 指定版本兼容，不依赖自定义 WebSocket Authorization Headers | `Browser(cdp_url=wss_endpoint)` 可直接操作页面 |
| CDP-010 | P1 | 对 tunnel 建连设独立超时，PoC 将初始目标设为 ≤8 秒，避免上游 Client 启动超时 | 建连超时返回 `TUNNEL_TIMEOUT`，并清理孤儿连接 |
| CDP-011 | P1 | 记录隧道元数据/字节数/延迟/异常，不记录默认 CDP 正文 | 安全审计可以定位链路，日志无 Cookie/页面正文 |
| CDP-012 | P1 | HTTP 代理、WebSocket Upgrade、Origin/Host、ping/pong 参数经过兼容性测试 | 反向代理后与直连效果一致 |

### 5.8 截图与媒体（MEDIA）

| ID | 优先级 | 功能要求 | 验收标准 |
|---|---|---|---|
| MEDIA-001 | P0 | 支持以 `instance_id + target_id` 定位当前页面并使用 CDP 截图 | 客户端得到有效 PNG，归属/时戳正确 |
| MEDIA-002 | P0 | 截图 API 必须校验用户的控制租约或专用查看授权 | 不得通过任意实例 ID 截取其他用户页面 |
| MEDIA-003 | P0 | 截图不能主动导航、关闭或切换用户页面 | 执行中截图前后 Agent 页面状态未被改变 |
| MEDIA-004 | P0 | 图片通过独立短时 HTTPS/WSS 媒体传输，不通过心跳控制连接传完整大图 | 大图传输不会使节点心跳超时 |
| MEDIA-005 | P1 | 截图记录 `capture_id`、实例/目标 ID、采集时戳、格式、尺寸、哈希与归属 | 能按任务/租约检索并审计 |
| MEDIA-006 | P1 | 设置截图大小与保留期限（建议默认 7 天），支持授权删除 | 超期文件可清理，证据目录权限正确 |
| MEDIA-007 | P2 | 页面 Screencast 帧订阅和观看者权限（V2） | 浏览器页面画面在客户端持续更新，控制会话不被打断 |
| MEDIA-008 | P2 | 观看者不能通过页面回显通道注入 CDP/控制事件（V2） | viewer token 无法请求写控制接口 |
| MEDIA-009 | P2 | 人工接管使用 lease fencing 转交控制权（V2） | 交接前旧 Agent 已无控制能力 |

| AUTH-005 | P0 | API Key、node secret、connect ticket、Cookie 不进入普通日志 | 审计/访问日志抽查无明文机密 |

错误体统一：
```json
{
  "error": {
    "code": "NODE_CAPACITY_REACHED",
```

## 8. WebSocket 控制协议与数据面要求

### 8.1 控制消息 Schema

```json
{
  "protocol_version": "1.0",
  "message_id": "uuid",
  "request_id": "uuid",
  "type": "CREATE_BROWSER",
  "node_id": "node-uuid",
  "connection_epoch": 7,
  "sent_at": "2026-11-16T08:00:00Z",
  "deadline_at": "2026-11-16T08:00:30Z",
  "payload": {
    "instance_id": "browser-uuid",
    "profile_id": "profile-test-a",
    "profile_mode": "persistent",
    "lease_epoch": 0
  }
}
```

消息应定义：`NODE_HELLO`、`NODE_WELCOME`、`NODE_SNAPSHOT`、`HEARTBEAT`、`HEARTBEAT_ACK`、`CREATE_BROWSER`、`STOP_BROWSER`、`GET_BROWSER`、`OPEN_TUNNEL`、`CLOSE_TUNNEL`、`SCREENSHOT`、`COMMAND_RESULT`、`ERROR`。控制心跳不得承载截图大图或大量 CDP 消息。

### 8.2 CDP 隧道建立协议

1. Client 获取 lease 并申请一次性 ticket。
2. Client 对 `wss://.../cdp/connect?ticket=...` 发起 Upgrade。
3. Gateway 校验 ticket 的有效期、一次性、当前租约/代际及用户身份，锁定其消费状态。
4. Gateway 生成 tunnel_id/nonce，通知对应认证的 Node 控制连接 `OPEN_TUNNEL`。
5. Node 验证实例与 lease epoch，**主动**连接中央 `/ws/v1/nodes/tunnel`，通过节点凭据与一次性 tunnel nonce 验证。
6. Node 在本地连接 `ws://127.0.0.1:<port>/devtools/browser/<guid>` 并进行健康确认。
7. Gateway 配对两个 WebSocket，转发内容与关闭事件，传递背压，不改变 CDP 指令。
8. 任一通道关闭、租约失效、管理员撤销或超时，Gateway/Node 释放相应资源。

**响应时间约束：** Browser Use 1.0 远程连接有自己的超时保护。PoC 中数据通道配对目标不超过 8 秒（可配置），真实网络需综合客户端 connect timeout 验证。不能出现 Gateway 已接受连接却无限等待节点的情况。

**连接兼容要求：** `cdp_url` 必须指向一个**浏览器级 WebSocket**，具备 Target attach/auto-attach 等功能。不能将自定义的 JSON API 或 Playwright WS 协议冒充 CDP。必要的 HTTP `/json/version` 代理属于扩展兼容项，并且要鉴权和重写返回地址。

## 9. 非功能需求（NFR）

| ID | 分类 | 要求与验收口径 |
|---|---|---|
| NFR-001 | 并发 | 至少 20 个同时 ACTIVE 的控制租约，连接到独立浏览器；建议 24 并发压测预留余量 |
| NFR-002 | 节点容量 | 单节点默认 4 个同时运行实例，配置可修改；10 个并发申请不会超配 |
| NFR-003 | 可扩展性 | 增加 Windows 节点后可自动注册/上报并加入调度，无需修改客户端连接配置 |
| NFR-004 | 浏览器版本 | Chrome for Testing 精确固定；Browser Use 依赖精确锁定，升级必须回归 |
| NFR-005 | 连接稳定性 | 稳定网络下每个 CDP 控制连接连续运行 60 分钟；压测统计异常断开率与重连成功率 |
| NFR-006 | 故障检测 | 节点断开控制通道默认 35 秒内标为不可调度；可根据环境配置 |
| NFR-007 | 一致性 | 不允许同一 Browser Instance 同时存在两个有效控制 Agent；故障恢复也必须保持不变量 |
| NFR-008 | 安全 | 跨主机所有 API/WS 使用 TLS；节点本机 CDP 仅 loopback；票据短时一次性；无机密明文日志 |
| NFR-009 | 审计 | 记录创建/关闭浏览器、Profile ACL 变更、凭据更新、租约授予与强制撤销 |
| NFR-010 | 恢复 | 中央重启后节点可重新建立控制通道并对账；不因重启而无条件重启所有 Chrome |
| NFR-011 | 数据保留 | 日志、审计和截图可配置保留；截图建议默认 7 天，审计建议默认 90 天（策略待确认） |
| NFR-012 | 可维护性 | Windows Worker/Central API 分离部署，提供版本信息、结构化日志、健康与状态诊断 |
| NFR-013 | 网络性能 | 统计 WSS 往返时延、网关额外延迟、吞吐和图像带宽；具体 P95 SLO 经跨网 PoC 定义 |
| NFR-014 | 容量退化 | CPU/内存不足时可拒绝新 Chrome，而非导致 VM 卡死或破坏已有测试 |
| NFR-015 | 隔离 | 默认 Profile 私有；同一节点内 Profile 隔离为逻辑隔离，面向不可信租户须部署独立 VM |
| NFR-016 | 可靠性 | 只允许一个 Worker 进程拥有节点的实例管理写权限；多 Uvicorn worker 禁用 |

**性能和可用性不能仅凭结构图承诺。** 第一个容量版本应开展 1/2/4 Chrome 单节点逐级压测，至少覆盖复杂页面、登录页面、图片加载、多个标签页和连续截图。生产 VM CPU/RAM 规模由压测确定；可以从 8 vCPU/16 GiB 的实验 VM 起测，但不是容量保证。

## 10. 安全与威胁模型

| 威胁 | 攻击/故障面 | 控制手段 |
|---|---|---|
| 节点身份冒用 | 使用伪造 node_id 连接中央 | 一次性注册 + 节点专属凭据 + epoch 校验 |
| 未授权 CDP 访问 | 直接连接 Chrome 端口 | loopback CDP + WSS Gateway 授权 + 防重放 ticket |
| 跨用户登录泄漏 | 使用其他用户 Profile | Profile ACL + 绑定归属 + 默认不共享 |
| 两个客户端争抢实例 | 双租约/延迟撤销 | DB 事务唯一约束、租约 fencing、节点核实 |
| 客户端绕过网关 | 让 Node 代理任意地址 | Node 仅解析本地 instance_id，不接受任意 host/port |
| 截图泄漏 | 截图 URL 被传给无权限用户 | 截图授权、短期下载链接、有效期与审计 |
| 票据在访问日志泄漏 | URL query 被记录 | 代理日志脱敏，票据一次性、短有效期 |
| Agent 中的恶意网页指令 | Browser Use 生成的代码与页面交互 | Agent 环境独立信任模型，测试账号最小权限、网段隔离 |
| Profile 跨系统访问 | 同一 Windows OS 用户可访问其他目录 | 操作系统 ACL；强租户隔离须分 VM/用户 |
| Windows 失联后的陈旧命令 | 中央重连/多副本竞争 | connection_epoch、lease_epoch、nonce 与断链清理 |
| 远程大图/大帧阻塞 | 截图阻塞控制心跳 | 媒体与控制分通道、流控/限额 |

## 11. 场景与验收测试用例（UAT）

| 用例 ID | 场景 | 期望 |
|---|---|---|
| UAT-001 | Windows 登入后任务计划程序启动 Worker | Worker 自动连中央，节点 ONLINE |
| UAT-002 | 断开 RDP 但不注销；执行 Browser Use 导航/截图 | Chrome 存活，CDP 页面操作可用；截图结果可读 |
| UAT-003 | 首次申请 browser，节点空闲 | 新 Chrome Headful 启动，租约 ACTIVE |
| UAT-004 | 一个节点已有 4 个实例，同时请求第五个 | 节点本地拒绝超额创建；中央选其他节点或排队 |
| UAT-005 | 将配置上限从 4 调整为 2 | 新增被限制，已有实例不被无条件强杀；回收以管理员策略进行 |
| UAT-006 | 同时向一个节点发起 10 个 CREATE | 实际最大运行数不超过配置上限 |
| UAT-007 | 两个 Agent 同时申请同一已登录 Profile | 只有一个有效租约/实例绑定 |
| UAT-008 | Agent 完成任务释放，另一个有权限用户申请同 Profile | Chrome/Profile 可复用，登录状态按站点规则保留 |
| UAT-009 | 未授权用户访问其他 Profile、截图、lease | 拒绝，且无数据泄漏 |
| UAT-010 | 客户端非法/过期/重放 CDP ticket | WSS Upgrade 拒绝 |
| UAT-011 | Window Node 无法被中央主动访问（NAT/无入站） | Node 仍可主动建立控制和 CDP 数据隧道 |
| UAT-012 | Kill Chrome 进程 | 标为 FAILED；不静默复用，保留相关诊断 |
| UAT-013 | Kill Windows Worker，Chrome 仍运行 | Worker 重启后恢复或隔离实例，不重复启动/占用 Profile |
| UAT-014 | Node 心跳中断超过 35s | 节点不可调度，旧租约不立即分配给别人 |
| UAT-015 | Node 重连且旧连接残留消息 | 旧 epoch 命令不执行，完成对账 |
| UAT-016 | 撤销 ACTIVE lease，旧 Agent 仍尝试发送 CDP | 旧通道被关闭，新的控制权在 fencing 完成后才可分配 |
| UAT-017 | 连续 1 小时进行 CDP 网页操作 | 不串线，隧道监控与日志正确 |
| UAT-018 | 6 节点 × 每节点 4 Chrome，24 并发浏览器操作压测 | 按测试计划统计性能/资源、成功率，容量不超配 |
| UAT-019 | 测试运行中对某 Target 截图 | 取得正确 PNG，不导航/关闭 Agent 页面 |
| UAT-020 | 并行大量截图与心跳 | 心跳不会被媒体数据长时间阻塞 |
| UAT-021 | 重复相同 Idempotency-Key 申请 | 同一请求返回同一结果，不创建额外 Chrome |
| UAT-022 | 中央服务重启，节点与客户端重新连接 | Node 对账、恢复可调度；旧浏览器未被无条件清理 |
| UAT-023 | Windows 用户注销/重启 | 服务器识别实例不可用，待人工登录后恢复节点 |
| UAT-024 | 非管理员尝试关闭其他用户正在使用实例 | 被权限系统拒绝 |
| UAT-025 | Browser Use 1.0.x `cdp_url` 经 Gateway 执行多标签页操作 | Target attach、点击、导航、截图通过；无协议转换错误 |
| UAT-026 | Node 伪造 Profile 路径或 CDP 目标端口 | Worker/中央拒绝任意路径/非实例映射目标 |

### 11.1 PoC 必过测试（正式开发前）

**所有以下测试均须通过，否则不得把“可实现”当作“已验证”：**

1. `browser-use==1.0.6`（候选版本）通过中央 WSS 浏览器级 CDP 连接远程 Windows CfT，完成打开网址、点击、读取文本和截图。
2. Chrome 运行在交互式 Windows 会话，断开 RDP 后仍能通过 CDP 完成页面动作/截图；锁屏行为单列记录。
3. 一个 Worker 同时启动四个独立 Profile，不串 Cookie，动态 CDP 端口无冲突。
4. Windows 无可入站服务的网络环境下，Node 主动发起 WSS 控制/数据两种连接。
5. 占用中的租约被撤销后，旧客户端无法继续发 CDP 操作，且新 Agent 不会与旧 Agent 双控。
6. 长 CDP 消息、连续截图、多标签页、WebSocket ping/pong、反向代理 TLS 与断线重连兼容。

### 12.2 质量门禁

- **架构门禁**：状态机、Profile 所有权、租约 fencing、CDP 隧道安全完成同行评审。
- **PoC 门禁**：第 11.1 节最小链路通过，失败项被明确归因和处理。
- **功能门禁**：P0 功能需求 + UAT 必选场景通过，OpenAPI/错误码与实现一致。
- **性能门禁**：20+ 并发容量、网关资源占用和节点恢复按同一测试脚本完成并留存报告。
- **发布门禁**：无未修复严重权限绕过，凭据/日志检查合格，安装/回滚/运维手册齐备。

## 14. 最终完成定义（Definition of Done）

V1 视为完成，当且仅当：

- 用户电脑与测试服务器均能使用同一套 SDK 通过中央 Gateway 控制 Windows Chrome。
- Windows 节点只主动连接中央服务，单节点**可配置**上限默认 4，Profile/实例相互隔离。
- 中央提供节点管理、调度、认证、Profile 授权、租约独占与安全 CDP 代理。
- Browser Use 已验证使用远程 `cdp_url`，支持网页操作、截图、多标签页；Agent 退出不强迫 Chrome 退出。
- 异常断线、Worker 重启、节点重连与租约撤销不会造成浏览器双控。
- 具备基础管理 API/管理页、结构化日志、指标、审计、部署与回滚指导。
- 所有 P0 需求满足，PoC 必过项和相关 UAT 测试有可复现记录。
